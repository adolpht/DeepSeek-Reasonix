## 一、产品定位与目标

### 1.1 愿景

**Reasonix = 你的 AI 工作伙伴**

一句话描述：**用自然语言下达指令，AI 自主规划步骤、调用工具、交付可验收成果。**

### 1.2 目标用户画像

| 用户类型 | 核心需求 | 当前痛点 |
|----------|----------|----------|
| **开发者** | 编码、调试、重构、代码审查 | IDE 切换成本高，Agent 不够自主 |
| **产品/运营** | 数据分析、PPT/报告生成、竞品调研 | 不会写代码，Excel 操作繁琐 |
| **行政/HR** | 文档整理、会议纪要、合同起草 | 重复劳动多，格式调整耗时 |
| **自由职业者** | 全栈办公（写文案+做表+做PPT+管日程） | 工具分散，需在多个软件间切换 |

### 1.3 核心目标

1. **零门槛**：无需命令行、无需配置环境，安装即用
2. **全场景**：编码 + 文档 + 表格 + PPT + 信息调研 + 日程管理
3. **真执行**：不是聊天，是真正帮你干活并交付成品文件
4. **安全可控**：所有操作本地执行，敏感数据不出机器
5. **可扩展**：插件/技能生态，社区共建能力

### 1.4 非目标（明确排除）

- 不做 SaaS / 云端托管 / 多人协作
- 不做图形化拖拽工作流编排
- 不做即时通讯软件（仅集成已有 IM）
- 不做通用搜索引擎（聚焦桌面级任务执行）

## 二、竞品分析与差异化

### 2.1 主要竞品对比

| 维度 | WorkBuddy (腾讯) | TRAE Work (字节) | Marvis (腾讯) | Kimi Work | **Reasonix (我们)** |
|------|------------------|------------------|---------------|-----------|---------------------|
| **定位** | 全场景职场AI工作台 | 编码+办公双模式 | OS级个人AI助手 | 本地Agent | **编码+办公双栖Agent** |
| **编码能力** | 弱 | 强 | 无 | 弱 | **极强（核心优势）** |
| **办公能力** | 强(PPT/Excel/Word) | 中 | 中 | 中 | **中→强（渐进增强）** |
| **远程控制** | 微信/企微/QQ/飞书/钉钉 | 无 | 微信小程序 | 无 | **微信/飞书/钉钉** |
| **模型支持** | 11种国产模型 | DeepSeek为主 | 混元/DeepSeek | Kimi | **DeepSeek优先+全兼容** |
| **本地优先** | 否(云端为主) | 否 | 部分 | 否 | **是（核心差异）** |
| **开源** | 否 | 否 | 否 | 否 | **是** |
| **插件生态** | MCP+2万技能包 | MCP | 有限 | 有限 | **MCP+Skill系统** |
| **价格** | $9.95/月起 | 免费 | 免费 | 免费 | **免费+增值** |

### 2.2 Reasonix 的三大差异化优势

1. **编码能力碾压级优势**：竞品均为办公优先、编码薄弱；Reasonix 以编码 Agent 起家，代码读写/调试/重构能力远超同类
2. **本地优先 + 开源**：所有数据不出本机，开发者/隐私敏感用户的首选；开源社区驱动，不锁定任何云服务
3. **Skill 声明式工作流**：用户可自定义 .md 文件描述工作流，无需代码；MCP 插件零侵入接入

### 2.3 需要补齐的短板

| 短板 | 竞品做法 | Reasonix 对策 |
|------|----------|---------------|
| 新手引导 | WorkBuddy 成长计划+积分 | 新手任务流 + 引导式首次体验 |
| PPT 生成 | WorkBuddy/TRAE 原生支持 | PPT 插件（P5） |
| 远程控制 | WorkBuddy Claw 功能 | IM 集成 + 远程指令（P6） |
| 模板市场 | WorkBuddy 2万技能包 | Skill 社区 + 模板库（P5） |
| 多模型切换 | WorkBuddy 11模型 | 多 Provider 已支持，优化 UI |
| 桌宠/趣味化 | WorkBuddy Buddy 盲盒 | 主题系统 + 轻量化个性化 |

## 五、核心功能详细设计

### 5.1 智能模式识别与切换

**目标**：用户无需手动切换模式，Agent 自动识别意图并路由

**实现方案**：

```
用户输入 → 意图分类器（轻量模型/API分类）→ 路由
  │
  ├── 编码意图 → 编码模式（代码读写/调试/Git）
  │     关键词：代码、函数、Bug、编译、测试、重构...
  │
  ├── 办公意图 → 办公模式（文档/表格/PPT/合同）
  │     关键词：周报、表格、PPT、合同、纪要、分析...
  │
  └── 助手意图 → 助手模式（搜索/日程/邮件/文件整理）
        关键词：帮我查、提醒我、整理、发邮件、安排...
```

**分类器方案**：
- 初版：基于关键词 + Skill 匹配的规则引擎（零成本）
- 进阶：调用小模型做意图分类（延迟 < 200ms）
- 高级：复用 planner_model 的规划能力，第一步即分类

### 5.2 首页与新手引导

**目标**：新用户 3 分钟内完成首次任务

**新手流程**：

```
安装启动
  → 欢迎页：「Reasonix 是你的 AI 工作伙伴」
  → 选择身份：[开发者] [办公人员] [自由职业者] [其他]
  → 配置 API Key（支持扫码/粘贴，可选本地模型跳过）
  → 引导任务：
      开发者 → 「让 Reasonix 帮你读一个代码文件」
      办公人员 → 「让 Reasonix 帮你分析一个表格」
      自由职业者 → 「让 Reasonix 帮你写一份周报」
  → 进入首页
```

**首页内容**：
- 问候语 + 时间感知（早上好/下午好）
- 快捷操作卡片（3-4 个，基于身份推荐）
- 最近任务列表
- 常用 Skill 快捷入口
- 每日提示（随机展示一个实用技巧）

### 5.3 PPT 生成能力（新核心功能）

**目标**：一句话生成专业 PPT

**技术方案**：

```
用户：「帮我做一个关于AI行业趋势的PPT，20页左右，专业风格」

Agent 执行流程：
1. 规划 PPT 结构（标题页/目录/章节/总结）
2. 调研内容（web_fetch 获取行业数据）
3. 调用 PPT 插件生成
4. 返回 .pptx 文件 + 预览
```

**PPT 插件设计**（`reasonix-plugin-slides`）：

| 工具 | 功能 |
|------|------|
| `mcp__slides__create_ppt` | 从 Markdown 大纲生成 PPT |
| `mcp__slides__add_slide` | 添加单页幻灯片 |
| `mcp__slides__apply_theme` | 应用主题模板 |
| `mcp__slides__add_chart` | 插入图表页 |
| `mcp__slides__export_pdf` | PPT 导出为 PDF |

**依赖**：`unidoc/unioffice`（纯 Go，支持 pptx 读写）

**Skill 示例**：

```markdown
---
description: 一句话生成专业 PPT
runAs: subagent
tools:
  - web_fetch
  - mcp__slides__create_ppt
  - mcp__slides__add_chart
  - mcp__slides__apply_theme
---

# PPT 生成 Skill

## 输入
- topic: PPT 主题
- pages: 页数（默认 15）
- style: 风格（professional/creative/minimal）
- language: 语言（默认中文）

## 执行步骤
1. 规划 PPT 大纲（封面/目录/章节/数据页/总结）
2. 如果涉及数据，web_fetch 获取最新数据
3. 调用 create_ppt 生成骨架
4. 逐章节 add_slide 填充内容
5. apply_theme 应用风格
6. 返回 .pptx 文件路径

## 约束
- 每页文字不超过 100 字
- 数据必须标注来源
- 图表页至少占 30%
```

### 5.4 信息调研能力（新核心功能）

**目标**：自动搜索、整理、分析信息，生成结构化报告

**技术方案**：

```
用户：「帮我调研一下2026年主流AI Agent产品，对比功能和价格」

Agent 执行流程：
1. 拆解调研维度（产品名/功能/价格/模型/定位）
2. 并行 web_fetch 多个来源
3. 提取关键信息，填充对比表
4. 生成调研报告（Markdown → docx）
5. 可选：生成对比 PPT
```

**新增工具**：

| 工具 | 功能 | 实现方式 |
|------|------|----------|
| `web_search` | 搜索引擎查询 | 集成搜索 API（SerpAPI/Bing） |
| `web_extract` | 从网页提取结构化信息 | 基于 web_fetch + LLM 抽取 |
| `compare_table` | 生成对比表格 | 输出 Markdown 表格 → xlsx |

**Skill 示例**：

```markdown
---
description: 竞品调研与对比分析
runAs: subagent
tools:
  - web_search
  - web_fetch
  - mcp__office__write_docx
  - mcp__sheet__write_sheet
---

# 竞品调研 Skill

## 输入
- topic: 调研主题
- dimensions: 对比维度列表
- output_format: docx | xlsx | both

## 执行步骤
1. web_search 搜索主题相关信息（至少 5 个来源）
2. 逐来源 web_fetch 获取详细内容
3. 提取关键数据，按维度整理
4. 生成对比表格（xlsx）
5. 撰写调研报告（docx）
6. 返回文件路径

## 约束
- 信息必须标注来源 URL
- 不确定的数据标注「待确认」
- 至少覆盖 3 个竞品
```

## 八、风险与约束

### 8.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| PPT 生成样式有限 | 产物不够精美 | 提供专业主题模板；支持导入 PowerPoint 模板 |
| 搜索 API 依赖第三方 | 成本/可用性 | 多搜索引擎备选；本地缓存；支持用户自带 API Key |
| 邮件协议兼容性 | 部分邮箱不支持 | 优先支持主流邮箱（Gmail/Outlook/QQ）；OAuth2 授权 |
| Wails 多窗口稳定性 | 悬浮窗崩溃 | 降级为系统通知 + 快捷键唤起主窗口 |
| 上下文窗口不足 | 复杂任务中断 | subagent 分片；自动压缩；模型自动路由 |

### 8.2 产品风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 功能膨胀导致臃肿 | 用户体验下降 | 模式隔离；渐进式展示；核心路径保持简洁 |
| 编码能力被稀释 | 核心用户流失 | 编码模式独立优化；零回归测试 |
| 隐私担忧 | 用户不敢用 | 本地优先；数据不出机器；敏感任务走本地模型 |
| 竞品快速迭代 | 市场份额被挤压 | 开源差异化；编码能力壁垒；社区驱动 |

### 8.3 设计约束（不可违背）

1. **本地优先**：所有数据处理在本机完成，不强制上云
2. **零回归**：编码模式功能不因改造而降级
3. **插件隔离**：新增能力通过 MCP 插件接入，主仓 `internal/` 不膨胀
4. **配置驱动**：所有新功能可通过配置开关，禁用后行为与改造前一致
5. **`CGO_ENABLED=0`**：所有新增依赖必须纯 Go
6. **缓存友好**：长任务走 subagent，主会话保持 system prompt 稳定
