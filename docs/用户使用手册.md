## 一、安装与快速开始

### 1.1 安装

```sh
# 任意系统（自动拉取对应平台原生二进制）
npm i -g Rexion

# macOS
brew install esengine/Rexion/Rexion
```

预编译归档（`darwin|linux|windows × amd64|arm64`）和 `SHA256SUMS` 见每个
[GitHub release](https://github.com/esengine/DeepSeek-Rexion/releases)。

### 1.2 从源码构建

```sh
make build      # -> bin/Rexion(.exe)
make cross      # -> dist/（六平台交叉编译）
```

特性：`CGO_ENABLED=0` 单二进制，唯一依赖是一个 TOML 解析库。

### 1.3 快速开始

```sh
Rexion setup                      # 配置向导 → ./Rexion.toml
export DEEPSEEK_API_KEY=sk-...    # 或写入 .env（见 .env.example）
Rexion chat                       # 进入交互式会话，运行 /init 生成 AGENTS.md
Rexion run "把 main.go 里的 TODO 实现掉"
Rexion run --model mimo-pro "给这个函数补单元测试"
echo "解释这段代码" | Rexion run    # 管道输入
```

## 二、配置系统

### 2.1 配置优先级

**flag > `./Rexion.toml` > `~/.config/Rexion/config.toml` > 内置默认值**

密钥经环境变量通过 `api_key_env` 注入，绝不写入配置文件。

### 2.2 Rexion.toml 完整示例

```toml
default_model = "deepseek-flash"   # 执行器；设 [agent].planner_model 可加规划器
# language    = "zh"               # 界面语言；为空则按 $LANG / $REXION_LANG 自动检测

[agent]
# planner_model = "mimo-pro"          # 可选的低频规划器
# subagent_model = "deepseek-pro"     # runAs=subagent skill 的默认模型
# subagent_models = { review = "deepseek-pro", security_review = "deepseek-pro" }
auto_plan = "off"                  # off|on；off 表示计划模式仅手动开启
# auto_plan_classifier = "deepseek-flash"   # 可选；只在边界任务上调用

[[providers]]
name        = "deepseek-flash"
kind        = "openai"
base_url    = "https://api.deepseek.com"
model       = "deepseek-v4-flash"
api_key_env = "DEEPSEEK_API_KEY"
# 预设：deepseek-pro、mimo-pro、mimo-flash @ api.xiaomimimo.com/v1

# 自定义供应商（任何 OpenAI-compatible 端点）
[[providers]]
name        = "my-proxy"
kind        = "openai"
base_url    = "https://my-proxy.example.com/v1"
models      = ["gpt-4o", "claude-3-opus"]
default     = "gpt-4o"
api_key_env = "MY_PROXY_API_KEY"

# Anthropic 原生供应商
[[providers]]
name        = "claude"
kind        = "anthropic"
model       = "claude-sonnet-4-20250514"
api_key_env = "ANTHROPIC_API_KEY"

[tools]
enabled = []                   # 省略/为空 = 全部内置工具
bash_timeout_seconds = 120     # 前台安全上限；0 表示不设工具层超时

[skills]
# paths = ["~/my-skills", "../shared/skills"]   # 额外自定义技能目录
# excluded_paths = ["~/.agents/skills"]         # 隐藏约定来源
# disabled_skills = ["review"]                  # 隐藏技能，直到 /skill enable <name>

[permissions]
mode  = "ask"                                # 兜底：ask|allow|deny
deny  = ["bash(rm -rf*)", "bash(git push*)"] # 任何模式下都硬阻断
allow = ["bash(go test*)"]                   # 从不询问

[sandbox]
# workspace_root = ""          # 文件写工具被限制在此目录；留空 = 当前目录
# allow_write    = ["/tmp"]    # write_file/edit_file/multi_edit 额外可写目录

[git]
# auto_fix_ci = false    # 为 true 时自动修复 CI 失败（每次修复仍需审批）
# auto_merge = false     # CI 通过后自动合并 PR（需分支保护）

[[plugins]]
name    = "office"
command = "Rexion-plugin-office"
```

### 2.3 内置 Provider 预设

| Provider | kind | base_url | 说明 |
|----------|------|----------|------|
| `deepseek-flash` | openai | api.deepseek.com | DeepSeek 执行器 |
| `deepseek-pro` | openai | api.deepseek.com | DeepSeek 规划器 |
| `mimo-pro` | openai | api.xiaomimimo.com/v1 | MiMo v2.5-pro |
| `mimo-flash` | openai | api.xiaomimimo.com/v1 | MiMo v2-flash |
| OpenAI | openai | api.openai.com | 官方预设 |
| Anthropic | anthropic | api.anthropic.com | 官方预设 |
| Gemini | openai | generativelanguage.googleapis.com | 官方预设 |
| Qwen | openai | dashscope.aliyuncs.com | 官方预设 |

`base_url` 不含版本段（如 `/v1`）时运行时自动补全。

## 三、命令行（CLI）

入口位于 [internal/cli/cli.go](../internal/cli/cli.go)，`Run()` 通过 `switch cmd` 分发顶层子命令。

### 3.1 顶层子命令

| 子命令 | 用途 | 主要参数 |
|--------|------|----------|
| `run` | 一次性 headless 执行：接收 prompt → 运行 agent → 输出结果 | `--model`, `--max-steps`, `--show-thinking`, `--metrics`, `--dir`, `--sandbox`, `--format (text\|json)`, `--timeout`, `--approval-mode (auto\|ask)`, `--diff`, `--quiet` |
| `chat` / `code` | 交互式会话（Bubbletea v2 TUI）；`code` 是 v0.x 遗留别名 | `--model`, `--max-steps`, `--continue/-c`, `--resume`, `--dangerously-skip-permissions/--yolo`, `--dir`, `--sandbox` |
| `serve` | HTTP+SSE 服务模式，事件流推送到浏览器 | `--model`, `--max-steps`, `--addr`（默认 `127.0.0.1:8787`）, `--resume` |
| `setup` | 配置向导：选语言 → 选 provider → 录入 API key | `--local/-l`（写入 `./Rexion.toml`） |
| `config` | 配置子命令（目前仅 `auto-plan`） | `config auto-plan [--local] [off\|on]` |
| `init` | 项目记忆入口（实际由会话内 `/init` skill 生成 `AGENTS.md`） | — |
| `acp` | ACP（Agent Communication Protocol）命令 | — |
| `mcp` | MCP 服务器配置管理（见下） | — |
| `mcp-server` | 将 Rexion 自身作为 MCP 工具服务器暴露 | `--transport (stdio\|http)`, `--addr`（默认 `0.0.0.0:9090`）, `--model`, `--max-steps`, `--dir`, `--sandbox` |
| `codegraph` | 代码图谱生成 | — |
| `doctor` | 健康检查，输出诊断报告 | `--json`（JSON 格式） |
| `skill` | Skills 市场浏览与安装（见 [§十七](#十七skills-市场)） | — |
| `session` | 跨设备会话同步（见 [§十八](#十八跨设备会话同步)） | — |
| `version` / `--version` / `-v` | 输出版本号 | — |
| `help` / `--help` / `-h` | 输出 usage | — |

### 3.2 mcp 子命令

```sh
Rexion mcp list                            # 列出已配置的 MCP 服务器
Rexion mcp add <name> [command [args...]]  # 添加 stdio 服务器
Rexion mcp add <name> --http URL           # 添加 HTTP 服务器
Rexion mcp add <name> --sse URL            # 添加 SSE 服务器
  # 通用 flag：--env K=V ... --header K=V ...
Rexion mcp remove <name>                   # 移除
Rexion mcp import                          # 从 cc-switch 导入
```

### 3.3 skill 子命令（Skills 市场）

```sh
Rexion skill search [query]               # 搜索社区 skills（空查询列出全部）
Rexion skill install <name> [--global]     # 一键安装 skill（--link 软链）
Rexion skill list-remote [--category c]    # 按分类列出仓库中的 skills
Rexion skill update                        # 强制刷新本地 skills 索引缓存
Rexion skill info <name>                   # 查看单个 skill 详情
```

索引本地缓存 24 小时；离线时回退到缓存副本。

### 3.4 session 子命令（跨设备同步）

```sh
Rexion session push [session-id]    # 推送会话到同步后端
Rexion session pull <remote-id>     # 拉取远程会话为新的本地会话
Rexion session list-remote          # 列出同步后端上的会话
Rexion session push-all             # 推送所有本地会话
# 通用 flag：--backend=file|http  --device-name=NAME
```

### 3.5 使用示例

```sh
# 一次性执行
Rexion run "修复 login.go 里的空指针"
Rexion run --model mimo-pro --metrics "重构这个函数"

# 服务模式
Rexion serve --addr 0.0.0.0:8787

# 把自己暴露成 MCP 服务器
Rexion mcp-server --transport http --addr 0.0.0.0:9090

# 诊断
Rexion doctor --json
```

## 五、内置工具

内置工具位于 [internal/tool/builtin/](../internal/tool/builtin/) 与 [internal/agent/](../internal/agent/)，通过 `init()` 自注册。下面按功能族分组。

### 5.1 核心文件 / Shell 工具

| 工具 | 只读 | 关键参数 | 说明 |
|------|------|----------|------|
| `read_file` | ✅ | `path`*, `offset`(0-based), `limit`(默认 2000) | 支持 BOM/UTF-16 自动检测、二进制探测 |
| `write_file` | ❌ | `path`*, `content`* | 保留原文件编码（GBK/UTF-16/BOM），自动建父目录 |
| `edit_file` | ❌ | `path`*, `old_string`*(唯一), `new_string`* | 精确字符串替换 |
| `multi_edit` | ❌ | `path`*, `edits`*(`[{old_string,new_string,replace_all}]`) | 原子性批量编辑，全成才写盘 |
| `bash` | ❌ | `command`*, `run_in_background` | Windows 无 bash 自动用 PowerShell；沙箱可选 |
| `ls` | ✅ | `path`(默认 "."), `recursive` | 列目录 |
| `glob` | ✅ | `pattern`* | 支持 `* ? []` 和 `**`；上限 1000 |
| `grep` | ✅ | `pattern`*(RE2), `path`(默认 ".") | 优先用 ripgrep；上限 200 |
| `web_fetch` | ✅ | `url`* | SSRF 防护（拒绝内网地址），HTML 提文本，1MiB 上限 |

`*` 表示必填。

### 5.2 后台任务族

### 5.7 多 Agent 协同族

## 六、MCP 插件系统

Rexion 是一个 MCP 客户端。`[[plugins]]` 的 `type` 选择传输：`stdio`（默认）启动本地子进程；`http`（Streamable HTTP）连接远程 `url`。工具以 `mcp__<server>__<tool>` 暴露给模型，与 Claude Code 一致；声明 `readOnlyHint: true` 的工具参与并行调度并命中权限层只读默认放行。

### 6.0.1 插件配置

```toml
[[plugins]]                       # 本地 stdio 服务器
name    = "office"
command = "Rexion-plugin-office"
# args    = ["--flag"]
# env     = { KEY = "value" }
# tools   = ["read_docx"]          # 可选：限制可见工具

[[plugins]]                       # 远程 Streamable HTTP
name    = "stripe"
type    = "http"
url     = "https://mcp.stripe.com"
headers = { Authorization = "Bearer ${STRIPE_KEY}" }   # ${VAR} / ${VAR:-default} 展开
```

### 6.0.2 兼容 Claude `.mcp.json`

把 `.mcp.json` 放到项目根目录，Rexion 会原样读取——其 `mcpServers` 规范与 `[[plugins]]` 字段一一对应。两处来源合并加载；同名时以 `Rexion.toml` 为准。

```json
{
  "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path"] }
  }
}
```

### 6.0.3 旧版兼容

`0.x` 的 `~/.Rexion/config.json` 仍被读取（读其 `mcpServers`、遵从 `mcpDisabled`），作为最低优先级来源。

### 6.0.4 MCP 服务器三要素

| 要素 | 暴露形式 |
|------|----------|
| **tools** | `mcp__<server>__<tool>` 工具调用 |
| **prompts** | `/mcp__<server>__<prompt>` 斜杠命令（空格分隔参数） |
| **resources** | `@<server>:<uri>` 在消息中引用拉入上下文 |

### 6.0.5 官方插件总览

| 插件 | 二进制 | 说明 |
|------|--------|------|

### 6.5 IM 即时通讯插件

**插件**：`rexion-plugin-im`（[cmd/rexion-plugin-im](../cmd/rexion-plugin-im/)）

支持企业微信（WeCom）、飞书（Feishu）、钉钉（DingTalk）三平台。两种连接模式：

- **Webhook 模式**（`start_bot`）：需公网 IP，所有平台都支持。
- **Stream 长连接模式**（`start_stream`）：钉钉/飞书无需公网 IP，Bot 主动连出。

**环境变量**：
- `IM_BOT_PORT`（默认 9876）、`IM_BOT_TOKEN`
- WeCom: `IM_WECOM_KEY`
- Feishu: `IM_FEISHU_KEY`（webhook）、`IM_FEISHU_APP_ID`/`IM_FEISHU_APP_SECRET`（stream）
- DingTalk: `IM_DINGTALK_KEY`/`IM_DINGTALK_SECRET`（webhook）、`IM_DINGTALK_APP_KEY`/`IM_DINGTALK_APP_SECRET`（stream）

#### 工具清单

| 工具 | 模式 | 说明 |
|------|------|------|
| `mcp__im__start_bot` | 读写 | 启动 webhook 模式 HTTP 服务（WeCom/Feishu/DingTalk） |
| `mcp__im__stop_bot` | 读写 | 停止 webhook 服务 |
| `mcp__im__start_stream` | 读写 | 启动 stream 长连接模式（钉钉/飞书，无需公网 IP） |
| `mcp__im__stop_stream` | 读写 | 停止 stream 模式 |
| `mcp__im__send_message` | 读写 | 主动发送消息到指定群 |
| `mcp__im__auto_start` | 读写 | 插件启动时自动按环境变量选择传输模式（配置 `auto_start_tool` 时自动调用） |
| `mcp__im__poll_commands` | 只读 | 阻塞等待新 IM 命令（默认 30s，上限 120s） |
| `mcp__im__list_pending_commands` | 只读 | 列出待处理命令 |
| `mcp__im__reply_message` | 读写 | 按 command_id 回复中间进度（不标记完成） |
| `mcp__im__mark_command_done` | 读写 | 标记命令完成并推送最终结果（推送失败自动入队重试） |
| `mcp__im__create_im_session` | 读写 | 为 IM 会话创建命名 session（可追溯） |
| `mcp__im__list_im_sessions` | 只读 | 列出 IM 会话记录（桌面端面板用） |
| `mcp__im__get_im_session` | 只读 | 查询单个 IM session 详情 |
| `mcp__im__delete_im_session` | 读写 | 删除单个 IM session 记录 |
| `mcp__im__clear_im_sessions` | 读写 | 清空所有 IM session 记录 |
| `mcp__im__set_work_mode` | 读写 | 设置会话工作模式（ask/plan/craft） |
| `mcp__im__get_work_mode` | 只读 | 查询会话工作模式 |
| `mcp__im__confirm_im_command` | 读写 | 确认或取消待二次确认的敏感命令 |

#### 远程命令（IM 端发送）

在钉钉/飞书/企业微信会话中发送：

| 命令 | 说明 |
|------|------|
| `/ask <问题>` | 仅问答，无副作用 |

**敏感操作**（删除/推送/部署/重启）必须在 5 分钟内回复 `确认` / `取消` 二次确认。工作模式按会话保持。

## 七、技能（Skills）系统

Skills 是可复用的 prompt 工作流定义，位于 [internal/skill/skill.go](../internal/skill/skill.go)。

### 7.1 Skill 文件格式

Markdown 文件 + YAML frontmatter，放在 `.rexion/skills/` 下。文件名 `<name>.md` 或目录 `<name>/SKILL.md`。

```markdown
---
name: weekly-report
description: 基于最近 7 天的 git log 自动生成周报 docx 文件
runas: subagent
allowed-tools: bash, read_file, mcp__office__write_docx
model: deepseek-pro
effort: high
---
（prompt body 正文）
```

### 7.2 frontmatter 字段

| 字段 | 说明 |
|------|------|
| `name` | 规范标识符（缺失则用文件名） |
| `description` | 一行描述（缺失则不进入模型索引） |
| `runas` | `subagent` 触发隔离子 agent 运行；默认 inline |
| `allowed-tools` | 逗号分隔工具白名单（仅对 subagent 生效） |
| `model` | subagent 模式下的模型覆盖 |
| `effort` | subagent 模式下的 effort |
| `context` | `fork` 等价于 `runas: subagent` |
| `agent` | 非空值等价于 `runas: subagent` |

### 7.3 发现目录

按优先级（高覆盖低）：`.rexion/skills/`（项目）> 自定义路径 > `~/.config/rexion/skills/`（用户全局）> 内置。

兼容扫描：`.agents/`、`.agent/`、`.claude/`（支持 Claude 等工具的 skill 迁移）。

### 7.4 调用方式

- **斜杠命令**：`/<skill-name>`（如 `/weekly-report`）
- **自然语言**：模型根据 `description` 自动匹配并调用（如说"帮我写周报"触发 `weekly-report`）
- **工具调用**：`run_skill(name="weekly-report")`
- **管理命令**：`/skills list|show|enable|disable|new|paths`

**两种运行模式**：
- **inline**（默认）：skill body 折叠为 tool result 注入当前会话
- **subagent**：在隔离子循环中运行，仅返回最终答案，保护主会话上下文

## 八、自定义命令

## 九、@ 引用机制

在消息里写 `@` 引用，发送前解析成带标签的上下文块：

| 写法 | 含义 |
|------|------|
| `@path/to/file` | 注入本地文件内容 |
| `@dir` | 注入目录清单 |
| `@<server>:<uri>` | 注入 MCP 资源 |

本地路径**只有真实存在**时才当作引用，普通 `@mention` 保持原文。敲 `/` 或 `@` 会弹出补全菜单：斜杠命令，或**逐层**文件导航（一次只列当前一层目录、可下钻）外加 MCP 资源。

## 十一、权限与沙箱

### 11.1 权限（策略层）

逐次调用把关，优先级：`deny` > `ask` > `allow` > 兜底 `mode`。

- 只读工具永远 allow
- writer 工具落到 `mode`（ask/allow/deny）
- `Rexion chat` 在 writer 调用前询问（`1` 本次 · `2` 本会话 · `3` 拒绝，兼容 `y/a/n`）
- `Rexion run` 自主运行但遵守 `deny`

```toml
[permissions]
mode  = "ask"
deny  = ["bash(rm -rf*)", "bash(git push*)"]
allow = ["bash(go test*)"]
```

### 11.2 沙箱（强制层）

文件写工具（`write_file` / `edit_file` / `multi_edit`）拒绝 `[sandbox] workspace_root` 之外的任何路径（默认当前目录），并解析符号链接与 `..`，防止越界。读不受限。

```toml
[sandbox]
# workspace_root = ""          # 留空 = 当前目录
# allow_write    = ["/tmp"]    # 额外可写目录
```

`bash` 在 macOS 默认进沙盒（Seatbelt）：命令只能写这些 root（外加临时目录与工具链缓存），`[sandbox] network` 为真时才能联网。其它平台暂回退为不沙盒运行。

## 十三、双模型协同

### 13.1 执行器 + 规划器

`Rexion setup` 保持首次体验极简；双模型协同需手动配置：

```toml
[agent]
planner_model = "deepseek-pro"   # 低频规划器
```

- 规划器看到已加载的记忆，拿到一小组只读研究工具，先检查相关文件再出计划
- 写入类和流程类工具只给执行器
- 各自独立、缓存稳定的 session

### 13.2 Subagent 模型

```toml
[agent]
subagent_model = "deepseek-pro"                          # 统一覆盖
subagent_models = { review = "deepseek-pro", security_review = "deepseek-pro" }  # 指定 skill 覆盖
```

默认继承执行器模型。

### 13.3 计划模式

交互式前端中计划模式默认手动开启。设置 `agent.auto_plan = "on"` 后，看起来复杂的任务会自动进入 plan mode：先只读生成计划，待用户批准后才编辑文件或执行有副作用命令。

- `auto_plan_classifier` 指定便宜的 provider（如 `deepseek-flash`），只在边界输入上调用，分类失败回退启发式
- `/auto-plan off|on`：会话内修改用户级设置
- `Rexion config auto-plan off|on [--local]`：shell/脚本修改（`--local` 写项目级覆盖）

每个计划步骤通过 `complete_step` 签收，必须提供证据（验证命令、diff 或手动检查）才能标记为完成——防止 agent 跳过未完成的工作。

## 十四、智能体工作台

除了单 Agent 循环，Rexion 还为并行、持久化和远程 Agent 工作流而生。

### 14.1 多 Agent + Worktree 隔离

`spawn_agent` 启动子 Agent（`default` / `worker` / `explorer` / `monitor` 角色）。当工作区是 git 仓库时，每个非只读 worker 在 `.rexion/worktrees/<agent-id>/` 下获得独立 worktree，分支名 `rexion/<agent-id>`，并行编辑互不冲突。`merge_worktree` 将变更合并回主分支并按文件报告冲突。子 Agent 关闭时自动清理 worktree。

**触发方式**：模型在复杂任务中自动调用，或用户说"并行处理这几个子任务"。

### 14.2 子 Agent 任务委派

`task` 工具派生子 agent 执行聚焦子任务，只返回最终答案，保护主上下文。支持后台运行（`run_in_background=true`），用 `wait` 收集结果。

## 十五、PR 与 CI 自动化

### 15.1 pr_monitor

通过 GitHub CLI（`gh`）查询 PR 状态、CI 检查、评论。只读，自动并行调度。

```
pr_monitor(pr_url="https://github.com/owner/repo/pull/123")
pr_monitor(pr_number=123, repo="owner/repo")
```

返回结构化结果：PR 状态（OPEN/MERGED/CLOSED）、CI 汇总（pending/success/failure）、最近评论。

### 15.2 auto_fix_ci

拉取失败 CI 日志，匹配常见错误模式（Go 编译错误、通用 `file:line: error`、`--- FAIL:`），返回结构化修复清单。`auto_apply=true` 时经 `ApprovalModal` 审批后通过 `edit_file` 应用建议编辑。

```
auto_fix_ci(pr_url="https://github.com/owner/repo/pull/123")
auto_fix_ci(pr_url="https://github.com/owner/repo/pull/123", auto_apply=true)
```

### 15.3 配置

```toml
[git]
auto_fix_ci = false    # 为 true 时自动修复 CI 失败（每次修复仍需审批）
auto_merge = false     # CI 通过后自动合并 PR（需分支保护）
```

### 15.4 review-pr skill 联动

`/review-pr --auto-fix` 审查 PR 差异并联动 CI 自动修复；`--auto-merge` 在 CI 通过后自动合并。

## 十六、IM 远程控制

通过 IM 插件从钉钉/飞书/企业微信远程触发 Agent。

### 16.1 启用方式

1. 配置环境变量（见 [§6.5](#65-im-即时通讯插件)）。
2. 插件启动时自动调用 `auto_start` 按环境变量选择传输模式（Stream 优先，WeCom 用 Webhook）。
3. 也可手动调用 `start_bot` 或 `start_stream`。

### 16.2 远程命令

在 IM 会话中发送：

| 命令 | 说明 |
|------|------|
| `/ask <问题>` | 仅问答，无副作用 |
| `/plan <任务>` | 先出计划，确认后执行（默认模式） |
| `/craft <任务>` | 直接执行 |
| `/status` | 查询运行中的会话 |
| `/cancel` | 取消待执行命令 |

### 16.3 安全机制

- **敏感操作**（删除/推送/部署/重启）必须在 5 分钟内回复 `确认` / `取消` 二次确认
- 工作模式按会话保持，可用 `set_work_mode` 切换
- 未确认的命令通过 `confirm_im_command` 释放或取消
- 中间进度用 `reply_message` 推送，最终结果用 `mark_command_done`（自动重试）

## 十八、跨设备会话同步

### 18.1 CLI 使用

```sh
# 推送当前会话
Rexion session push

# 推送指定会话
Rexion session push <session-id>

# 推送所有本地会话
Rexion session push-all

# 拉取远程会话为新的本地会话
Rexion session pull <remote-id>

# 列出同步后端上的会话
Rexion session list-remote

# 指定后端
Rexion session push --backend=http
Rexion session push --device-name="我的笔记本"
```

后端类型：
- `file`（默认）：`~/.config/rexion/sync/`
- `http`：HTTP 同步服务

### 18.2 桌面端使用

侧边栏 → **跨设备同步**图标（Smartphone 图标）→ 弹出 `SessionSync`：
- 显示远程会话列表
- 每个远程会话显示二维码，手机扫码接力
- 推/拉按钮同步会话

> 弹窗形式，不占用主会话窗口。

## 十九、故障排查

### 19.1 doctor 命令

```sh
Rexion doctor          # 文本诊断报告
Rexion doctor --json   # JSON 格式
```

### 19.2 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `md_to_pdf` 不可用 | pandoc 未安装或未加入 PATH | 安装 pandoc 并重启 |
| 模板库为空 | `.rexion/templates/` 不存在或无文件 | 创建目录并放入模板 |
| 文档预览显示「无法预览」 | docx 页级渲染未实现 | 点击「用默认应用打开」 |
| `read_sheet` 返回空 | 路径错误或格式不支持 | 确认是 xlsx/csv 且路径正确 |
| `query_sheet` 报错 | SQL 语法错误或字段不存在 | 检查字段名和 WHERE 语法 |
| `web_search` 不可用 | 未设 `SEARCH_API_KEY` | 配置环境变量 |
| slides 带水印 | 未设 `UNIDOC_LICENSE_API_KEY` | 申请免费 key |
| 日历集成不可用 | 非 Windows/macOS 或缺 Outlook/Calendar.app | 使用对应平台 |
| `pr_monitor` 报错 | `gh` 未安装或未认证 | `gh auth login` |
| `auto_fix_ci` 不应用修复 | 未设 `auto_apply=true` 或未通过审批 | 在桌面端审批弹窗中批准 |
| `dws_check` 提示未安装 | dws CLI 不在 PATH | 安装 dws 或设 `DWS_PATH` |
| `figma_import` 报错 | 未设 `FIGMA_TOKEN` | 配置 Figma personal access token |
| Computer Use 点击坐标偏移 | 多显示器或 DPI 缩放 | 使用 `computer_window_list` 确认窗口位置 |
| 桌面端白屏 | `frontend/dist` 未构建 | `cd desktop/frontend && pnpm build` |
| Linux WebKitGTK 渲染异常 | 4.0/4.1 版本不匹配 | 加 `-tags webkit2_41` 构建 |
| macOS 首次启动「已损坏」 | Gatekeeper 隔离属性 | `xattr -dr com.apple.quarantine /Applications/Rexion.app` |
| Windows SmartScreen 拦截 | 未签名 | 「更多信息 → 仍要运行」 |
| IM Stream 模式连不上 | AppKey/AppSecret 错误或网络问题 | 检查环境变量与网络 |
| IM Webhook 收不到消息 | 无公网 IP 或端口未开放 | 改用 Stream 模式或暴露公网 |

## 附录：技术架构

```
┌─────────────────────────────────────────────────────────┐
│              前端层（chat TUI / HTTP+SSE / Wails 桌面）   │
└───────────────────────────┬─────────────────────────────┘
                            │  transport-agnostic
┌───────────────────────────▼─────────────────────────────┐
│              control.Controller（内核，单一入口）         │
│   Provider registry · Tool registry · Gate · Compose    │
└───────────────────────────┬─────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
┌──────────────┐  ┌──────────────────┐  ┌──────────────┐
│  内置工具     │  │  MCP 插件（子进程）│  │  Skill 系统   │
│  (init 自注册)│  │  stdio / HTTP    │  │  inline/subagent│
└──────────────┘  └──────────────────┘  └──────────────┘
```

三层可扩展性，全部藏在内核按名解析的 registry 之后：

1. **Registry**：`Provider` 与 `Tool` 是接口；内核没有 `switch model`
2. **编译期内置**：provider 和 tool 通过 `init()` 自注册，`main` 用 blank import 拉入。新增内置 = 一个文件 + 一行 import
3. **运行时插件**：配置里声明的可执行文件，通过 stdin/stdout 上的 newline-delimited JSON-RPC 2.0（MCP 约定）通信
